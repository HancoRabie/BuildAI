# BuildAI text on Minecraft signs (Java 1.21.1)

**Why blank signs happened:** sign text does not live in the placed
`minecraft:oak_sign[rotation=...]` block state. It is four lines on a
Minecraft `SignBlockEntity`, and BuildAI previously only transferred block
states. The 30-station Redstone Benchy exposed this missing feature.

## Model-authored signs

The model must return a root `signs` array **in addition** to operations
placing the actual corresponding sign blocks. Example:

```json
{
  "name":"Redstone Benchy",
  "width":16,"height":8,"length":16,
  "operations":[
    {"kind":"fill","block":"minecraft:oak_sign[rotation=0,waterlogged=false]",
     "x1":3,"x2":3,"y1":2,"y2":2,"z1":6,"z2":6}
  ],
  "signs":[
    {"x":3,"y":2,"z":6,"lines":["01","NORTH","1-tick","Signal"]}
  ]
}
```

- 512 labels maximum, four lines per sign, 24 Unicode codepoints maximum
  per line, plain literal strings only.
- Optional `back_lines`; everything defaults to blank if absent.
- Each label MUST refer to an existing real sign block at the same local
  blueprint coordinates; duplicates and non-sign coordinates are rejected.
- A blank sign block is not a complete requested room/station label.
- No arbitrary NBT/chat components, rich text, clickable run commands,
  or impersonation of command-block permissions are accepted.

## Placement and persistence

1. AI generation compiles `operations` then verifies `signs` metadata.
2. Blueprint JSON includes labeled sign data through chunked client→server
   upload, without executing any commands.
3. Full 90° rotations move label XYZ coordinates with the sign block.
4. The server places the sign as a physical block in Creative/Survival,
   then writes text to its actual front/back sign block entity in the
   final normalization phase. Sign text is not typed by the AI using a
   simulated sign editing GUI.
5. Saved Sponge v3 `.schem` files include literal sign block entities
   and a separate inert `BuildAISignPlan` metadata field. On reimport
   BuildAI accepts its bounded metadata, but continues ignoring arbitrary
   external block-entity payloads.
6. Manual redstone re-normalization doesn't overwrite user-edited signs.

## Currently running or already placed builds

Updates DO NOT rewrite the Minecraft game instance already running or
retroactively add text to a blueprint generated by an older version.

To identify tests in the current Redstone Benchy, use the original prompt's
stable order (five rows of six) **only if the construction actually follows
that layout**. Inspect the circuitry to verify each station; do not assume
a blank board proves the numbers match the intended rows.

After restarting with the updated code, a *fresh* generation or a revision
with a proper `signs` array can produce functional labels. Do not need
to rebuild the whole existing test merely to check its baseline behavior.
